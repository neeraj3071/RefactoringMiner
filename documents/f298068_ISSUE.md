# Issue Report: False "Replace Attribute With Variable" from Extract Method

## Commit
- **SHA**: f298068141991b07f36b4ce9d1e2b4f92a81318d
- **Repository**: stefaanvermassen/virtual-museum-app
- **File**: Assets/Scripts/Museum/MuseumTile.cs

## Problem
RefactoringMiner reports that class fields were "replaced" by local variables that exist in a completely different scope (inside an extracted method).

## Detection Summary
- **Total**: 12 refactorings
- **Extract Method**: 6 detections (100% correct ✅)
- **Replace Attribute With Variable**: 6 detections (0% correct ❌)
- **Overall Precision**: 50%

## False Positive Example

### What RefactoringMiner Reports
```
Replace Attribute With Variable: upObject : GameObject 
replaced by frontSide : var in method CreateFace()
```

### Actual Code Reality

**upObject is a CLASS FIELD (still exists)**:
```csharp
private GameObject upObject, downObject, leftObject, ...; // Line 14
```

**frontSide is a LOCAL VARIABLE (inside CreateFace)**:
```csharp
GameObject CreateFace(Vector3 localPosition, Vector3 angles){
    var ob = new GameObject();
    ob.transform.parent = gameObject.transform;
    var frontSide = GameObject.CreatePrimitive(PrimitiveType.Quad); // Local var
    frontSide.transform.parent = ob.transform;
    ...
    return ob; // Returns ob, not frontSide
}
```

**They coexist and serve different purposes**:
- upObject: Class field storing the returned GameObject
- frontSide: Temporary local variable during object construction inside CreateFace()
- NO REPLACEMENT OCCURRED

## Root Cause

When Extract Method refactoring happens:

1. **Before**: `upObject = GameObject.CreatePrimitive(...);`
2. **After**: `upObject = CreateFace(...);`
3. **Inside CreateFace**: `var frontSide = GameObject.CreatePrimitive(...);`

RefactoringMiner sees the similar pattern (GameObject.CreatePrimitive) and incorrectly concludes that:
- Old: upObject assigned directly
- New: upObject "replaced" by frontSide

**Reality**: upObject still exists as a field and is assigned the RETURN VALUE of CreateFace(). The frontSide variable is an internal implementation detail, not a replacement.

## Systematic Error Pattern

**Occurs when**:
- Extract Method creates local variables
- Original code had field assignments
- Local variables have similar types/patterns to fields

**Result**: Tool reports "Replace Attribute With Variable" for EVERY field that was refactored through Extract Method

**Scope**: This created 6 false positives in this single commit (one for each GameObject field: upObject, downObject, leftObject, rightObject, frontObject, backObject)

## The Good News

✅ Extract Method detection worked perfectly (100% precision)
- Correctly identified CreateFace() extracted from Start() and UpdateEdges()
- Properly tracked all 6 usage sites
- Accurate code location mapping

This shows RefactoringMiner CAN handle Extract Method in Unity C# code when:
- No complex C# features (var with inference, properties)
- Clear method extraction patterns
- Explicit types

## Critical Fixes Needed

### 1. Scope-Aware Variable Validation
```
Before reporting "Replace Attribute With Variable":
- Check if the "old" variable still exists in after-code
- Verify variables are in the same scope level
- If both exist, DO NOT report replacement
```

### 2. Extract Method Context Awareness
```
When Extract Method is detected:
- Mark newly created local variables as "internal to extracted method"
- Do NOT consider them as replacements for calling-scope variables
- Only report replacement if original field/variable is truly gone
```

### 3. Semantic Purpose Validation
```
Verify that variables serve the same purpose:
- Storage vs temporary computation
- Return values vs intermediates
- Lifetime and usage patterns
```
